# Сервис оценки по фотографиям

Разбирает снимки лота двумя слоями и отдаёт результат агенту ASSESSOR.

## Два слоя и зачем их два

**Детектор** — YOLO, модель `car-damage.pt`, работает локально и бесплатно.
Знает шесть классов: `dent, scratch, crack, glass shatter, lamp broken, tire flat`.
Даёт тип дефекта, уверенность и долю площади кадра, посчитанную по маске.

**Разбор** — внешняя модель, понимающая содержимое снимка. Видит то, чего у
детектора нет среди классов: сорванную крышу, открытый лонжерон, сработавшие
подушки, ржавчину, следы огня и воды. Она же считает стоимость ремонта.

Детектор не используется как фильтр перед разбором. Машина без крыши не
попадает ни в один его класс и возвращает пустой список — ровно как целая.
Пустой результат детектора не отличает «повреждений нет» от «повреждение
такое, что модель его не назовёт», поэтому разбор идёт по каждому лоту.

## Один запрос на лот

Все снимки лота уходят одной пачкой. По отдельности стоимость ремонта
посчитать нельзя: одно и то же крыло, попавшее в три кадра, будет оплачено
трижды. Плюс это один запрос вместо десяти — при суточном лимите
бесплатного тарифа разница решающая.

## Лимиты и перенос на следующий день

Бесплатный тариф Gemini: у Flash 20 запросов в сутки, у Flash Lite — 500.
Поэтому основная модель — Lite, а Flash запасная; выбор по квоте, не по качеству.

Ограничители стоят ниже тарифных потолков, чтобы упираться в свой предел,
а не собирать отказы:

| Переменная | По умолчанию | Потолок тарифа |
|---|---|---|
| `VISION_RPM_LIMIT` | 12 в минуту | 15 |
| `VISION_DAILY_LIMIT` | 450 в сутки | 500 |

Счётчик расхода лежит в `/data/vision-budget.json` — контейнер перезапускают,
а лимит у Google суточный, и отсчёт с нуля после рестарта упёрся бы в их отказ.

Когда бюджет исчерпан, сервис возвращает `deferred: true`. Это не отказ и не
«повреждений нет»: очередь в `src/photos/queue.js` откладывает лот до
следующих суток через `markDeferred`, не расходуя счётчик попыток. Частичного
разбора не бывает — половина осмотренных снимков может не содержать
сорванной крыши, и лот прошёл бы как чистый.

## API

### POST `/api/photos/assess`

```json
{
  "lotNumber": "12345678",
  "context": "Автомобиль: 2018 Toyota Camry, заявленное повреждение: rear.",
  "photos": ["base64_1", "base64_2"]
}
```

Успешный ответ:

```json
{
  "available": true,
  "provider": "gemini",
  "model": "gemini-flash-lite-latest",
  "photosAnalyzed": 3,
  "lotNumber": "12345678",
  "assessment": {
    "photosUsable": true,
    "visibleDamage": ["Разбитая задняя левая фара", "Деформация задней панели"],
    "damageZones": ["rear", "left"],
    "missingParts": ["Крышка багажника", "Заднее стекло"],
    "severity": "severe",
    "structuralConcern": true,
    "airbagsDeployed": null,
    "batteryAreaAffected": null,
    "rustSeverity": "light",
    "fireOrFloodSigns": null,
    "repairPlan": [
      { "work": "Замена крышки багажника", "partsUsd": 450, "laborUsd": 200 }
    ],
    "repairCostMin": 1300,
    "repairCostMax": 2100,
    "confidence": "medium",
    "notes": "краткий технический вывод"
  },
  "detector": {
    "totalDamages": 3,
    "damageTypes": { "dent": 2, "lamp broken": 1 },
    "detectableClasses": ["crack", "dent", "glass shatter", "lamp broken", "scratch", "tire flat"]
  }
}
```

`null` в `structuralConcern`, `airbagsDeployed`, `batteryAreaAffected` означает
«по этим снимкам не определить» и намеренно отличается от `false`.

`repairCostMin` и `repairCostMax` идут в `calculateMaxBid`. Без них
`repairCostSource` падает с `photo` на нормативы, и предельная ставка
перестаёт опираться на снимки.

Отложенный лот:

```json
{ "available": false, "deferred": true, "reason": "суточный лимит исчерпан: 450 из 450" }
```

### GET `/health`

Отдаёт статус, путь к модели, список её классов и расход за сутки. Список
классов здесь не для красоты: однажды сервис работал со стоковой моделью,
которая повреждений не знала вовсе, а `/health` показывал «healthy».

## Развёртывание

Внутри контейнера порт 3001, наружу проброшен **3002** — 3001 на хосте занят.

```bash
scp -r src/yolo-service root@2.28.54.56:/opt/bronvera-agents/src/

ssh root@2.28.54.56
cd /opt/bronvera-agents/src/yolo-service
docker build -t yolo-assessor:latest .
docker run -d --name yolo-assessor -p 3002:3001 --memory=3g \
  -v /opt/bronvera-agents/data:/data \
  --env-file /opt/bronvera-agents/.env.vision \
  yolo-assessor:latest
```

Ключ поставщика лежит в `/opt/bronvera-agents/.env.vision` с правами 600
и в репозиторий не попадает.

## Настройки

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `VISION_PROVIDER` | `gemini` | поставщик: `gemini` или `gigachat` |
| `GEMINI_API_KEY` | — | ключ Google AI Studio |
| `GEMINI_MODEL` | `gemini-flash-lite-latest` | основная модель |
| `GEMINI_FALLBACK_MODEL` | `gemini-flash-latest` | если основная перегружена |
| `VISION_MAX_PHOTOS` | `0` | 0 — смотреть все снимки лота |
| `VISION_MAX_EDGE` | `1280` | до скольких пикселей ужимать снимок |
| `MODEL_PATH` | `/app/car-damage.pt` | веса детектора |
| `CONF_THRESHOLD` | `0.35` | порог уверенности детектора |

Порог 0.35 подобран на реальных снимках: вмятины от града набирают 0.46 и при
0.5 терялись, а на 0.1 появляются ложные срабатывания с 0.17–0.21.

## Зависимости образа

`python:3.11-slim` не содержит системных библиотек, с которыми слинкован
OpenCV. Без `libgl1` и `libglib2.0-0` контейнер падает при старте на
`ImportError`, а вызывающая сторона получает HTTP 503 — это уже случалось.

Torch ставится из CPU-индекса PyTorch: на CPX22 нет видеокарты, а CUDA-сборка
раздувала образ до 9.5 ГБ. Сейчас 3.3 ГБ.
